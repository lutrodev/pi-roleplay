# 模型与思考设置

连接、模型能力和调用偏好分别管理。连接保存地址、协议与密钥；模型保存能力和当前渠道的参数规则；主会话、Writer、任务子代理选择模型及思考选项。Pi 负责模型协议、流式输出和 Agent 循环，应用负责验证选择、适配思考控制并记录最终请求参数。

日常添加模型只需选择模型（或填写模型 ID），名称和能力自动识别。配置页仅显示名称和默认思考；渠道没有可调档位时，直接显示“自动”，无需设置。能力覆盖、思考参数映射、生成限制和连接覆盖统一收在默认折叠的“高级设置”中，已有自定义配置会标明并保留，无需重新填写。

会话中的思考菜单只列实际可选的强度。“自动”表示由模型服务决定思考方式，其他选项按响应速度与思考深度说明，不展示 tokens 或渠道参数。勾选项始终对应当前生效值；单独选择后，可用“恢复默认”或“跟随主模型”恢复继承。没有可调档位且没有需要恢复的覆盖时，只显示自动状态，不打开菜单。窄屏使用思考图标与当前档位，完整说明仍在控件名称中。已有不可用的设置仍保留提示与重新选择入口。

## 能力与控制

名称、图片输入、思考能力、上下文窗口、最大输出按“手动设置 → 服务返回信息 → 精确模型目录”的顺序解析。仅声明 `reasoning: true` 不会启用一组未经确认的强度档位。

思考控制还需要匹配实际渠道与 API 协议。官方端点的精确目录信息可以自动使用；陌生代理或带前缀的模型 ID 不会自动套用原厂参数。服务只返回 `supportsReasoning: true` 或 `supported_parameters: ["reasoning"]` 时，只能确认能力，不能确认支持哪些档位或能否关闭。

相同协议、相同端点的精确模型匹配会保留目录中的完整兼容规则，包括温度支持、工具约束与消息级强度；连接的内部 ID 不影响识别。服务预设只提供连接及协议提示，不能把所有 Qwen 模型都认定为开关模式。模型明确声明的档位和关闭限制优先于这类通用提示，手动 `reasoningControl` 则按用户配置生效。

设置 → 模型 → 配置 → 高级设置中的“思考控制”支持：

| 方式 | 可选内容 | 常见参数 |
| --- | --- | --- |
| 服务默认 | 服务默认 | 不发送思考控制字段 |
| 开关 | 开启、明确支持时的关闭 | Qwen `enable_thinking`；DeepSeek / GLM `thinking.type` |
| 强度档位 | 渠道明确支持的档位 | OpenAI `reasoning_effort`；Responses / OpenRouter `reasoning.effort`；Anthropic `output_config.effort` |
| 思考预算 | 各档位的 tokens 数 | Anthropic `thinking.budget_tokens` |

手动配置时只勾选实际支持的档位，并填写服务要求的值。编辑器提供的初始值是模板，不是已验证的能力。多个档位不得发送相同值。是否支持关闭单独声明：OpenAI 格式需填写明确的关闭值，例如渠道支持的 `none`。省略参数不能当作关闭。

## 默认与继承

新配置不主动指定思考参数，由服务决定。可以为每个模型设置应用中的默认档位。调用时按以下规则解析：

1. 有明确的调用选项时使用该选项，包括“自动”（服务默认）或“关闭”。
2. 固定选择模型但未指定思考选项时，使用该模型的默认设置。
3. 跟随主模型时，一同继承主模型当次的有效路由；子代理仍可单独指定思考选项。
4. 会话子代理未覆盖时，使用全局子代理设置。

例如主模型设为“高”：Writer 选择“跟随本会话主模型”会使用高；Writer 固定选择同一个模型但没有指定强度，会使用该模型自己的默认值。界面会标明独立设置或继承，并显示当前生效选项。

切换模型会清除旧模型的会话强度。已有的不支持选项会显示不可用，并在调用前报错；不会自动降档。思考预算与正文共享输出上限，至少为正文保留 1024 tokens；预算不足时在发送前拒绝请求，不静默压缩预算。

高级设置中的“单次输出限制”（配置字段 `outputTokens`）通常留空，应用自动使用不超过模型限制和 8192 tokens 的额度。它是主代理、Writer、任务子代理、连接测试和前情总结共同遵守的硬上限，调用方只能进一步缩小。前情总结按“显式思考预算 + 最多 4096 tokens 正文”申请总额度，并受该上限约束；不会把 4096 tokens 当作含思考在内的固定总额度。

Anthropic 的基础地址可填写服务根地址或以 `/v1` 结尾的地址，模型发现和生成使用一致的路径，保留网关前缀与原始配置。支持消息级强度的模型在显式选择档位时保留历史强度、签名绑定和缓存设置，本次强度写入最后的消息级控制；保存的回复元数据使用实际发送的映射值。切到服务默认或关闭时，不再残留会强制指定强度的消息。

Responses 的思考摘要展示与强度控制分别处理：支持思考的模型默认请求 `reasoning.summary: "auto"`。选择服务默认时省略 `effort`，仍可请求摘要；摘要请求本身不代表设置了强度或保证服务返回摘要。

## 配置文件

`config/models.json` 中省略能力字段表示自动识别。`reasoningControl` 省略表示自动识别控制方式；`{ "mode": "provider" }` 表示始终仅提供服务默认选项。`defaultReasoningEffort` 省略表示服务默认。

以下是一个已经按渠道文档确认参数的自定义模型示例：

```json
{
  "models": [{
    "provider": "my-service",
    "model": "exact-channel-model-id",
    "keyEnv": "RP_MODEL_API_KEY",
    "api": "openai-completions",
    "baseUrl": "https://service.example/v1",
    "reasoningControl": {
      "mode": "effort",
      "format": "openai",
      "levels": { "low": "low", "high": "high" },
      "off": "none"
    },
    "defaultReasoningEffort": "low"
  }],
  "main": { "provider": "my-service", "model": "exact-channel-model-id", "reasoningEffort": "provider-default" }
}
```

`format` 可选 `openai`、`openai-responses`、`deepseek`、`qwen`、`zai`、`openrouter`、`anthropic`，必须与连接协议一致。预算模式仅用于 Anthropic，`levels` 值为整数。使用专用关闭字段的格式以 `off: true` 声明关闭支持；未声明时不提供关闭选项。

Pi 内置的其他原生协议仍可使用服务默认。额外思考控件目前只适配上述三种可配置的连接协议，不把 Google、Bedrock 等原生协议当成 OpenAI 格式。

旧配置里的能力布尔值保留其原意，不再隐含“所有强度都可用”。依赖旧版自动中档的配置应按需明确设置模型默认；未知渠道已有显式档位需要先补充控制规则，或主动改为服务默认。密钥、模型 ID 和故事中的路由不会被自动重写。

## 验证与请求记录

连接测试使用服务默认参数，只证明一次基础调用可达，不证明每个思考档位都被上游执行。轨迹详情 → 请求显示解析后的选择和 Pi 生成后实际提交给 HTTP SDK 的参数；分别记录为 `provider:request` 与 `provider:parameters`。参数证据包含思考字段、输出上限、实际发送的温度，以及 Anthropic 消息级强度的位置和值，不包含密钥、提示词或回复内容。消息级强度模式下，顶层缓存基准值与本次强度可以不同，界面会解释如何读取。

“实际请求参数”证明应用发出了什么，不能证明中转服务内部执行了什么。服务默认不会被记录成关闭。旧记录缺少实际参数时，界面会明确标注其局限。

设计参考 [OpenCode 的模型选项与 variants](https://opencode.ai/docs/models/) 的能力驱动选择，以及 DSH 对缺省、关闭和档位映射的严格区分。服务元数据依据 [OpenRouter Models](https://openrouter.ai/docs/guides/overview/models)、[Claude Models API](https://platform.claude.com/docs/en/api/models) 和 [Cline 能力说明](https://docs.cline.bot/api/models)。当前适配范围以本项目支持的三种协议和上述控制格式为准。
