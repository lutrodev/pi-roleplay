# Writer 预置历史

入口：**设置 → Writer 预置历史**。只作用于固定 Writer，Chat / Agent 模式均可使用；主模型和可编辑的任务子代理不接收这份历史。

此功能是通用的原生历史编辑器。每轮保留“用户消息 → 工具步骤 → 助手最终回复”的编辑结构，可以自由构建工具调用，编辑工具名、参数 JSON、结果 JSON、成功/失败标记及步骤顺序。写作仅作为内置案例的内容，不限制可编辑的消息或工具。

内置案例为两轮写作交流：第一轮通过 `read` 读取写作要求，第二轮通过 `read` 读取叙述风格备忘。工具参数和结果沿用文件读取的格式，只提供写作参考。题材在各轮用户消息的“题材：”后留空，助手最终回复完全留空，供用户手动填入生成的正文。文件名和参考文字都是可编辑的案例数据，没有专用工具协议。

初始化与“载入内置案例”共用 `packages/rp-core/src/agents/writer-history-example.json`，每次载入返回独立副本。应用启动不会自动替换已有配置。“载入内置案例”和“恢复空模板”会替换当前编辑草稿并关闭注入，点击保存后才生效。

注入默认关闭。关闭时可以保存未完成草稿；启用并保存前，用户消息、助手最终回复和工具步骤需要通过通用格式校验。

支持 **1–8 轮**，可添加、删除和上下移动整轮。空模板和普通内置案例仍从两轮开始，已保存的轮数不会自动改变。每轮包含一条非空用户消息、1–16 个串行工具步骤和一条非空助手最终回复。步骤可增加、删除、上移、下移；参数和结果必须是对象根节点的 JSON。工具名限 1–64 位 ASCII 字母、数字、下划线和连字符。调用 ID 自动生成，不能编辑。参数和结果的 JSON 原文保留，包括大整数和高精度数字。

## 实际发送

Pi 的系统提示与历史消息分开构建。普通文本模式的逻辑顺序为：

1. 当前 Writer 系统提示。
2. 第一轮用户 → 助手工具调用 → 工具结果 → … → 助手最终回复。
3. 其余各轮按保存顺序采用同一结构，全部保留。
4. 本次真实写作上下文与当前附件。

历史使用 Pi 原生 `user` / `assistant` / `toolResult` 消息，工具错误保留 `isError`，由现有适配器转换为各提供商协议。没有添加“示范”文本包装；不会执行历史工具，也不改变真实模型权限、安全约束或 Writer 已有的只读文件工具。预置内容不是实际授权证明。

预置历史只支持文本、串行工具调用与对象 JSON；不支持在历史中插入系统消息、reasoning、图片或并行工具批次。只读预览展示原生消息内容；接收方模型标识和计量占位由运行时填入。本轮图片附件仍由运行时传递。

## 工具参数正文模式

在同一页面的 **本轮正文交付 → 交付方式** 中选择 **工具参数正文**。已有普通文本和工具参数配置继续按各自模式运行，不会被自动替换。

这个模式把正文通过真实的模型工具调用参数交付，应用再提取为 Writer 的文本结果。可编辑工具名、正文字段名、工具说明、字段说明、系统补充说明和三条调度消息。默认工具名为 `writer_display`，正文字段为 `display_stream`。工具名不能与当前 Writer 的只读工具重名。

实际请求结构为：

1. Writer 系统提示，加可选系统补充和本轮交付协议。
2. 全部原生预置历史。
3. 预置用户调度 → 预置助手确认 → 本轮执行请求及图片附件。
4. 工具列表保留真实只读工具，并增加正文交付工具；本轮完整写作上下文（含角色资料、历史剧情、当前输入和写作 brief）放入交付工具的 description，字段说明放入参数 schema。

调度消息、系统补充及工具/字段说明支持 `%TOOL_NAME%`、`%OUTPUT_FIELD%` 文本占位符。预置历史中的工具名与 JSON 保持用户原文；修改交付工具或字段名后，如需让案例与新协议一致，应同时编辑历史示例。不会执行 JavaScript、shell 或酒馆脚本，不解释随机骰子宏。案例中的 `cat` 与文件名仅是呈现方式，不代表真实文件已存在或命令已运行。

模型可以先读取真实参考附件，最后单独调用一次正文交付工具。工具只接收一个非空字符串字段，不修改文件或故事状态。应用把该字段流式显示为草稿，保留身份宏展开、20 万字符上限、停止和取消处理。完整参数必须通过严格 JSON 与 schema 校验；截断、格式错误、重复交付、与其他工具混合交付、普通文本代替交付或提供商报错都不会生成成功的 Writer 结果，也不会提交剧情。澄清或拒绝回复也可通过该字段交付，再由父模型按原有 `rp_reply` 流程呈现。

原始工具调用、`toolUse` 结束状态、工具接收结果和完整请求均保留在轨迹中，不伪装成模型普通文本输出。预置历史仍不执行；追加的两条调度消息标记为“预置交付调度”，本轮真实正文交付另记为一次工具调用。主模型和任务子代理不接收这些配置。

交付配置随历史一起冻结、摘要和备份。上下文溢出恢复时保留同一份历史及调度配置，只更新工具说明中的实际上下文。普通文本模式可保留交付配置草稿，但不会增加工具或调度消息。提示文本不会修改模型推理设置，也不保证任何模型的内容接受或绕过效果。

## 终端归档模式

点击 **载入终端交付案例**，在 **终端案例版本** 中选择：

- **简单版 · 旧电台（2 轮）**：保留扩写前的许岚与旧电台故事，每轮 1 个交付步骤；两轮消息、终端显示文本及系统/调度/字段说明均保留原版。历史编译为 2,778 字符，工具说明中的案例为 1,705 字符。
- **六轮版 · 常来做客的她（6 轮）**：使用 6、4、4、4、4、4 步的连续场景和完整终端协议。

选择版本只改变待载入的选项；取消不会改动当前草稿。确认载入后替换全部历史与交付设置并关闭注入，启用、保存后才影响新生成。已有配置和已开始运行的冻结快照不会被自动修改。切换会恢复该版本的内置原文，不单独存储每个版本的自定义编辑。

六轮版使用原创成年人物故事《常来做客的她》。两位主角分别为 26 岁的服装店陈列师和 28 岁的摄影师，正文描写来访、整理旧台灯、晚饭、市集邀约及次日布置，属于非露骨日常故事。已保存的旧案例不会因升级而被覆盖，需要主动重新载入。所有案例、系统声明、调度消息和工具/字段说明均可编辑。

六轮版包含 **6 轮独立的用户消息 → 工具步骤 → 助手回复**，步数依次为 **6、4、4、4、4、4**。前四轮依次为来访清理台灯、晚饭留下邀请、回应邀请、收拾道别；第五轮明确推进到周日早晨，第六轮在市集开场前布置摊位。每轮约 400–800 字符的完整正文，与当轮输入和状态一一对应。

第一轮依次进入并确认目录、列目录、读取参考资料、读取当前状态与请求、检查文件类型和统计并读取正文、交付显示流。后五轮依次查阅前情、读取状态与新请求、读取当前完整章节、交付显示流。相关读取合并到同一步，后续不反复加载全部参考资料。共 20 条 Bash 操作记录与 6 条交付记录；历史编译长度为 35,909 字符，比此前两轮长版（12/10 步）的 31,240 字符增加约 15%，工具说明中的案例为 22,997 字符。

示例使用 `/workspace/archive/visiting-days`，真实资料的呈现根目录是 `/workspace/archive`，提示符统一为 `writer@linux`。各轮快照新增对应章节、输入与状态，保留早先文件且不包含未来轮的文件。`file --mime` 显示文本类型，`wc -l -c` 的行数和字节数从正文计算；人物位置来自 TSV 状态表，`tail` 与 `grep` 摘录来自同一套文件。目录采用 `ls -1F` 的单列形式，避免列宽和时间戳影响记录。容器验收通过工具服务在持久 Bash 中执行全部 20 条操作记录，只映射测试工作区的绝对根路径，逐项比对输出与状态。

完整交付文本保留在最后一个步骤的参数中。若助手最终回复与配置字段的字符串完全相同，工具说明中的归档以该参数为引用，不再重复整段回显；不同回复、错误结果或不完整草稿仍保留原文。存储内容和参数/结果 JSON 原文不会被改写。

这个模式重组整个 Writer 请求：

1. **消息链**仅包含终端系统声明 → 用户调度 → 预置助手确认 → 执行请求。全部原生工具历史归档到工具说明，不再混在真实消息里。
2. **工具说明**依次容纳交付规则、`writer_rules.txt` 中的原 Writer 系统规则、全部示例归档和真实上下文。角色、世界、风格、变量、摘要、自定义提示、写作 brief、附件元数据和引用会话保留；仍按本轮已选上下文的布局、顺序与启用状态装配。
3. **输入归档**按真实消息角色分类，历史用户消息逐条变成独立的文件预览；历史助手消息标记为终端输出，并保留剧情/讨论区别。本轮多条输入全部保留，最后一条显示为 `cat chapter_01_preview.txt` 的内容，随后是读取 `chapter_01.txt` 的请求。用户文字里的同名标记不会改变消息分类。当前图片仍作为图片附件发送。
4. **字段说明**定义完整终端显示流：定位目录，读取归档中实际存在的规则、人物、风格、状态和用户预览，按需查阅前情，再检查章节类型和统计，最后读取完整正文。场景核对是简短的可见状态，不是内部推理。文件名、目录和命令都是虚构呈现，不执行 Linux 命令；预置的 Bash 记录不会为本轮增加 Bash 工具或权限。
5. **响应解包**流式提取配置的字符串字段，保留终端显示和正文全文。只移除当前运行的合成输出调用；没有其他工具调用时，将交给 Agent 的结束状态转换为 `stop`。合成载体不执行、不生成工具接收结果。真实只读调用仍可在先前或同一响应中执行。原始提供商响应保留其工具调用与 `toolUse`，解包后的 `writer:assistant` 另行记录，便于对照。

每次运行生成 16 位随机会话标识，追加到可编辑工具名前缀（最多 47 字符）。该名字、示例和调度链在运行开始时冻结，重试与上下文压缩沿用；下一次运行使用新标识。协议字段支持 `%TOOL_NAME%`、`%OUTPUT_FIELD%`、`%SESSION_ID%`。示例 JSON 原文无损保留。`tool_choice` 显式使用 `auto`，不会覆盖用户配置的模型推理参数。

终端归档要求严格、完整的指定输出字段。普通文本、空字段、错误字段、附加字段、重复合成调用、损坏 JSON、截断、取消或提供商失败会明确报错，不把残缺内容当成已完成章节。父模型仍按现有机制决定提交剧情或呈现普通回复。

页面的 **请求结构预览** 使用示例会话标识和本轮资料占位符；真实请求可在 Writer 轨迹的系统提示、消息和工具定义中检查。长度区域分别显示参与校验的历史编译字符数、配置字节数和实际工具说明中的案例字符数，后者不含本轮真实资料。应用内置的三种模型适配器（OpenAI Chat Completions、OpenAI Responses、Anthropic Messages）都经过实际 HTTP 请求体断言验证，包括简单版两轮的 2 个交付步骤，以及六轮版的 26 个步骤、各轮用户输入与完整章节，确保实际请求只包含所选版本。Docker 部署验收另检查实际网络接收的请求。测试使用合成提供商响应，不代表任何外部模型必然遵从提示或能绕过其限制。

## 保存、冻结与审计

- 单份全局配置保存于 SQLite 的 `writer.history` 设置，文档格式 `version: 1`，增加可选的 `delivery` 配置；未包含它的既有记录仍表示普通文本。事务替换和 `expectedRevision` 比较保证原子保存；冲突返回 409，不覆盖另一份编辑。
- 配置 JSON 上限 262,144 UTF-8 字节；启用时普通文本和工具参数模式的编译消息上限为 20,000 UTF-16 字符，终端归档模式的全部编译历史上限为 40,000 字符，均含消息与 JSON 包装。工具交付配置另限 20,000 字符。关闭时不校验内容完整性，但仍校验结构、步骤上限与存储大小。
- 队列任务开始执行时捕获 revision、SHA-256 摘要、消息数、工具调用数和完整消息内容。运行内重试、资料刷新和上下文压缩都沿用该快照；后续保存只影响下一次开始的运行。
- `runtime:writer-history` 模型诊断记录保存完整原文快照；每次 Writer 的 `provider:request` 保存实际 Pi 消息与无损的 `historyMessagesJson`，`writer.completed` 保存历史元数据。
- 轨迹页在系统提示之后按原生角色显示全部预置历史，工具参数和结果可查看。界面标记“预置历史”；不产生真实 `tool.started` / `tool.finished` 事件，不计入实际工具调用数或运行异常数。真实模型请求的输入 tokens 仍由提供商正常计量。
- 预置历史只归属于实际接收它的 Writer 子代理，不增加会话轮次，也不作为执行时间概览中的模型或工具调用。重新生成归入同一会话轮次的下一次尝试；展开“历史尝试”时，仍可查看旧尝试冻结的 Writer 预置版本。删除回复后，相关 Writer 过程随回复退出当前有效轨迹，完整原始记录保留在历史尝试中。
- 配置随应用数据库冷备份与恢复。损坏或不支持的配置版本明确报错，不静默重置或跳过注入。已有会话日志不回填新历史；停止或失败时不把预置助手回复当作本轮正文。
