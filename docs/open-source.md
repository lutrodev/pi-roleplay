# 开源范围与发布检查

## 应公开什么

公开源码包含应用、领域层、协议、内置 Skills、原创合成测试、构建与部署脚本、使用文档、MIT 许可、迁入代码来源和依赖许可说明。应用的六个 WebP 背景文件有固定来源记录和校验值。

不要直接压缩整个开发目录。使用：

```bash
pnpm release:check
pnpm release:pack
```

`pack` 先重新检查，再从同一份已扫描内容生成 `output/releases/pi-roleplay-VERSION-source.tar.gz` 和 SHA-256 清单。tar 文件统一权限与时间戳、清空用户/用户组元数据，不带本机目录或 Git 历史。包内脚本保持可执行。

## 保留在本地的内容

| 内容 | 原因 |
| --- | --- |
| `.env`、`secrets/`、`config/` | 部署身份、凭证与个人模型路由 |
| `.dev/`、`.deploy/`、`state/`、`data/`、`backups/` | 调试与运行数据、会话、密钥、备份与更新记录 |
| `output/`、`.cache/`、`.playwright-cli/` | 本机日志、工具记录、截图及生成中间产物 |
| `docs/evidence/`、`docs/migration.md`、`design.md` | 旧验收记录含个人路径、用户角色卡信息和截图；没有整体公开授权 |
| `scripts/test-summary-v4f.ts` | 面向特定本机配置的付费模型验收脚本，不作为通用开发入口 |
| `skills/custom/` | 用户自定义内容，仅公开空目录占位文件 |
| `node_modules/`、构建输出、SQLite 与日志文件 | 依赖、生成产物或私有数据，不是公开源码 |

这些文件只加入忽略与打包排除规则，不删除本地原件。`.gitignore` 用于日常提交，`.gitattributes` 为 Git 归档增加一道排除；`scripts/release-policy.ts` 的明确公开规则才是源码包的文件来源。新增未知文件、未登记图片和符号链接会阻止打包。

## 检查内容与限制

检查公开工作区的常见凭证格式、硬编码秘密、个人路径，以及本地密钥文件的内容是否被复制到公开文件。报告只输出文件、行号和规则，不输出秘密值。还检查 Markdown 是否链接到未公开文件，以及背景文件是否与已审查校验值一致。

若目录是独立 Git 仓库，检查当前暂存区和所有本地引用可达的历史 blob；已删除的私有文件仍会被发现。规则匹配不能证明没有所有类型的敏感信息。历史作者邮箱、提交消息、远端其他引用和未安装依赖不属于此扫描范围。

当前整理源码时没有独立 `.git`，因此不能据此声称原仓库历史安全。首次公开可从生成的干净源码包建立新仓库；如果要公开既有仓库，应另外审查完整历史及提交身份信息。若密钥曾泄露，需要在提供方撤销，不能只删除文件。

许可证说明见 [第三方说明](../THIRD_PARTY_NOTICES.md)。这里准备的是源码发布；公开预构建 Docker 镜像和二进制时，应针对实际平台与镜像依赖重新完成许可材料检查。
