# 本地开发

## 启动与停止

安装 Node.js 24、项目锁定的 pnpm 11.23.0，并启动 Docker。使用普通用户在源码根目录执行 `./dev.sh`，或者 `pnpm dev`。脚本会根据锁文件和运行时指纹决定是否需要安装依赖；不会自动升级版本。原生模块安装如果提示缺少编译器，需补齐系统的 Python 3 / C++ 编译工具后重试。

前端默认 `http://127.0.0.1:18767`，API 使用 18768，工具容器通过随机的本机端口提供鉴权接口。端口被占用时明确报错，不杀进程，也不改成一个未告知的地址。用 `--web-port` 和 `--api-port` 指定空闲端口；3080 始终不允许使用。

首次密码在 `.dev/admin-password`；通过 `cat .dev/admin-password` 查看。需要重置时，停止调试后执行 `./dev.sh password`，新的密码仍写入同一文件。密码重置只影响调试数据库。

启动成功后在网页添加自己的模型连接。调试模式使用真实模型配置，不自动接入模拟提供方。完整端到端回归中的合成模型是另一套临时测试环境。

前端使用 Vite HMR，后端使用 Node 的 watch 模式重启。后端重启会中断进行中的模型任务，因此调试生成流程时应先等待任务结束再修改后端。工具源码变化后 Ctrl+C 并重新运行入口，Docker 会利用缓存重新构建。

Ctrl+C 会关闭本次启动的前后端进程，并停止、移除专属 Compose 容器与网络；保留 `.dev/` 文件和构建镜像。强制杀死启动器可能留下容器，下次启动会接管同一目录专属的开发 Compose 项目；锁文件对应进程仍存在时拒绝重复启动。

## 数据和执行边界

| 目录 | 用途 |
| --- | --- |
| `.dev/data/` | 调试 SQLite、附件、头像和背景 |
| `.dev/workspaces/` | 调试故事及命名工作区的文件 |
| `.dev/skills/` | 仅调试环境使用的自定义 Skills |
| `.dev/session_key` | 调试会话和凭证加密密钥 |
| `.dev/tool_token` | 调试应用与工具容器的令牌 |
| `.dev/admin-password` | 调试初始/重置密码 |

开发入口清除继承的 `RP_*` / `COMPOSE_*` 设置，再构造本次调试配置，不加载生产 `.env` 或模型清单。不要将真实部署的数据目录连接或软链接到 `.dev/`。同一源码目录只运行一套调试环境；多套并行开发使用不同源码目录与端口。

工具容器以当前普通用户的 UID/GID 运行，只挂载调试工作文件、只读附件、只读自定义 Skills 和工具令牌。不挂载应用数据库、会话密钥、模型密钥、源码目录或 Docker socket；容器根文件系统只读。所有故事共享同一个工具容器，这不是故事间或租户间的隔离。

自定义前后端端口时，启动器会同步配置访问 origin 与 Vite 代理，不需要修改生产 `.env`。`dev:web` / `dev:server` 只供已手动准备好环境的独立排查；通常使用统一入口即可。

## 验证

`pnpm verify` 执行类型检查、领域与应用测试、生产构建。`pnpm test:backup` 测试部署脚本的备份边界和更新失败路径。公开包内的测试使用原创合成资料，不依赖个人数据或旧项目。

`pnpm test:entrypoints` 在临时目录复制通过公开检查的源码，实际构建 Docker 镜像，并验证默认外部反代、真实 OpenResty 的登录/SSE/附件、构建失败保护、成功更新、启动失败停服、可选 Caddy 恢复和代理模式切换。只使用合成会话，不调用付费模型；完成后清理测试容器和临时数据。

浏览器合成环境使用 `pnpm build` 后运行 `pnpm test:browser:fixture`。命令输出临时地址和合成登录信息；默认只使用合成模型，退出时清理临时数据，不应用作个人故事存储。

界面修改同时遵守 [UI 边界状态约定](ui-states.md)，复用反馈、校验、图片和进度组件，并覆盖失败恢复、未保存输入、长内容与小屏幕状态。

需要真实容器隔离和恢复验证时，请按 [部署验收](deployment.md#开发与部署验收) 构建测试镜像并运行容器测试。验收输出写入本地 `docs/evidence/`，不会进入公开源码包。
